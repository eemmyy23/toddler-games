# ABC 123! — architecture

## Shape
A static PWA: no framework, no build step, GitHub Pages. Offline via `sw.js`.
Everything the child sees is **data, config or a module**. The engine (`abc/core/`) names no subject, language,
profile or word. Adding a word, a language, a module or an age profile never edits `abc/core/`, `abc.html` or `sw.js`.

```
abc.html                    markup of the shell + views (incl. the `#backdrop` layer behind the stage), all CSS (tokens → components); loads abc/manifest.js, then its scripts
abc/manifest.js             GENERATED by `node tools/check.js --fix`: script order, offline file list, version hash
abc/config.js               name, version, icons, languages, modules, sections (tabs), age profiles, base language
abc/concepts.js             one line per concept: stable ASCII id + picture, e.g. C('cow', '🐄'); groups: GROUP('fruit', 'apple banana …')
abc/art.js                  drawings as ART(id, svg): a concept id replaces that concept's emoji, a profile id is its bike,
                            an icon key is a UI icon (`grid`), `hand-0…5` are the counting hands
abc/lang/<code>/grammar.js  LANG(): name, flag, bcp47, dir, letters, forms() + optional hooks (see LANG below)
abc/lang/<code>/strings.js  STRINGS(): UI text and templates (tabs, praise, plural/gender templates, aria labels, profile names …)
abc/lang/<code>/words.js    the word for each concept + explicit grammatical forms
abc/lang/<code>/info.js     "What is it?" cards, keyed by concept id (optional)
abc/modules/<id>/module.js  MODULE(): builds its own items per language; declares tiles (learn view + game), needs, checks
abc/modules/<id>/lang/<code>.js  MSTRINGS(): the module's tile labels, spoken questions and own text
abc/core/registry.js        global ABC + the registration functions (contracts: below)
abc/core/i18n.js            esc; I18N: t (string, function, or object chosen by `g` then plural category), graphemes, list, collator,
                            units, splitUnits, highlight, capFirst, upper
abc/core/content.js         INK palette; CONTENT: builders thing/word/glyph/picture/group/set and helpers words, byId, things, pic, svg,
                            the, example, exclaim, listing, sayThe, palette, alphabet, navText, made
abc/core/tiles.js           the one rule set "what a tile shows and when" — used by the app AND tools/check.js
abc/core/services.js        $, onTap/onTapIn (act on click: keyboard works, no palm taps), onScrub (tap or drag a finger across a row/column of
                            targets: each target acts once as the finger enters it; keyboard clicks too; never swipes the stage), wait, shuffle, PAUSE/TALK timings,
                            store (localStorage or session, `abc2.` keys; `store.legacy(k)` reads an old `abc.` key once, so stars and language survive the rename), sound (sfx, tone), speech (SPEECH, speak, hush),
                            audio (ensureAudio, quietAudio), confetti, calm (reduced motion)
abc/core/views/*.js         VIEW(): card, read, count, play, dial (a view's id is its file name)
abc/core/games/*.js         GAME(): find, howmany, sort
abc/core/shell.js           hubs, tabs, flags, profiles, navigation, ‹ › ▶ controls, language switch, index, search, info cards, input,
                            speech sequences, service-worker updates, install bar, APP
sw.js                       precaches MANIFEST.files under cache 'toddler-<version>' and deletes older ones; scripts whose ?v= is the current
                            version are cache-first, the rest network-first (cache after 3 s or offline); an open app checks for an update on
                            every return to the foreground and reloads the next time it goes to the background once a new version took over
tools/check.js              content, config, markup, CSS-token, engine-literal, PWA-scope and no-comment checks; manifest generator (CI)
tools/fast.js               layout check, no server (needs playwright): every language × hubs, learn tiles (first, middle, last, longest
                            item; Read: 6 longest words), games × 7 sizes (phones, tablet portrait/landscape, desktop), oldest profile (CI)
tools/smoke.js              browser test: every language, every game, choice rules, speech, keys, background, search, offline, clock (hour cycle per
                            language, spoken times, dragging and tapping the dial, day/night backdrop and its contrast) (CI)
```

## Key rules
- **Ids, not words.** Words and info cards are keyed by concept id (`cow`); saved progress by tile id + stable item id — never by text or emoji.
- **Explicit forms.** Each language writes its forms (RO `def`, `pl`, `plDef`, `g`, `mass`, `plOnly`; DE `g`, `pl`, `mass`, `plOnly`; EN `art`, `pl`, `mass`, `plOnly`;
  all: `unique` — one of a kind, so "That's …" uses the definite form: the sun, soarele, die Sonne; `ex: false` — never a letter example;
  `syn` — synonyms; `homonym` — same spelling as another concept). Grammar code only assembles them; school rules are checks:
  `checkForms` (warning) and `checkWord` (error), not generators.
- **Base language.** Missing UI strings fall back to `config.baseLanguage` (en); `check.js` reports every missing key.
- **Modules don't share data.** `build(code)` returns the module's own namespace; its tiles read only that.
  Language data a module reads is declared in `needs` (e.g. `numbers`, `sayLetter`) and checked for every language.
- **One implementation of every shared part.** Every item is built by a `CONTENT` builder — `thing` (a dictionary word), `word` (a thing with
  `w`/`syl`/`forms`, for Read), `set` (a list of words + module sentences), `glyph` (text: digits, letters, symbols), `picture` (a drawing or swatch; optional `word` shown under it, default the name),
  `group` (several pictures as one card) — with one palette (`CONTENT.palette(i)`), `I18N.capFirst`, the language's `exclaim`/`listing` templates and
  `CONTENT.sayThe`. Builders fill the defaults (`big`, `nav`, `bubble` = label) and the "That's …" grammar (`thats`) and freeze the item. A module adds its
  own fields but cannot override a built one (only `say`, `examples`, `sound` are open); `check.js` rejects an override, any item (or group member) not built
  by `CONTENT`, and a tile that misses an item another language has.
- **A tile is never shown broken** (`abc/core/tiles.js`): a learn tile needs a registered view, its label and items; its game needs a working learn tile,
  its game label and ≥ `needs` items from both `pool(items, 0)` and `pool(items, Infinity)`. Otherwise it is hidden in that language.
- **Age profiles** (config, ascending): curious 2–4 · explorer 4–7 · scientist 7–12, shown as bikes in the top bar on every
  hub; anyone may switch. A tile's start age (`tile.ages[0]` or `module.ages[0]`; the end is informative) picks its profile (start < upper: 4 → explorer);
  the tile shows from that profile upwards (higher profiles add, never remove) and wears that profile's badge
  (left → right in profile order). A tile that is not complete in a language is not shown at all (no "coming soon").
- **Speech** uses only a voice of the current language (local first, `LANG.voices` preferred, never another language's). No voice → 🔇 on the flag.
- **Globals.** Content files only call the registry. Views and games use `APP`, `CONTENT`, `I18N`, `Tiles`, `ABC` (read-only), `esc` and the services
  (`$`, `onTap`, `onTapIn`, `onScrub`, `speak`, `sfx`, `store`, `confetti`, `calm`, `wait`, `shuffle`, `PAUSE`). The shell owns its state (language, profile, section, hub);
  `APP.set({ profile, section, hub })` and `setLang(code)` change it (tests use them, then `render()`); `APP.set` does not persist.

## UI rules
- **One class and one base style per component** (`.pill`, `.rbtn`, `.seg`, `.group`, `.sheet`, `.card`, `.label`, `.dot`, `.scroll`, `.nav`, `.bub`).
  Every tappable card (hub tile, example, letter tile, form, count row, info line, index cell, search row, question) is a `.card`: one background,
  shadow, transition and pressed look. A variant is a modifier class (`.primary`, `.small`, `.link`, `.caps`, `.txt`, `.accent`, `.tight`, `.dim` …);
  it restyles only its own component.
- **Tokens.** Colours, radii, type, spacing, sizes, shadows, durations and easings live in `:root`; `check.js` rejects any px/vh/vw (above 2px hairlines), colour,
  `cubic-bezier` or s/ms duration outside `:root`. A data colour (letter, number, swatch) is passed as `--c` and read by `.ink` (text), `.dot` or `.pt` (fill); a stagger as `--i`. The breakpoints (width ≤ 440, width ≤ 350, height ≤ 700, landscape height ≤ 450, portrait) only reassign tokens (checked);
  the reduced-motion block turns animation off.
- **One selected look**: `.on` — the amber ring (`--ring` outline) and a small lift — for everything picked or being read aloud. Keyboard focus is a different look
  (`:focus-visible`, the dashed `--focus` outline). The dial's `.held` hand is grab state, not selection (`APP.stop()` clears `.on`, never the held hand).
- **Every tap target is a `<button>`** with a name (text or `aria-label`), never nested in another button; `#glyph` (it holds part buttons) is the one tappable box, and Space/Enter speak its line.
- **One visibility mechanism**: the `hidden` attribute (`[hidden]` wins over any display); breakpoints and compact classes may size a token to 0, never hide.
- **One content column**: `--col` / `--gut` place the top bar, every screen, the ‹ › arrows, the sheets and the tab bar.
  Controls fixed above the tab bar carry `data-low` (only those in the lower half that overlap the screen's column limit it — side arrows in landscape do not); a screen too tall for the space calls `APP.fit(el, compactClass)`
  (compact first, then scale to fit); text too wide for its box uses `APP.fitText(el, innerSelector)` (sets `--fit`) — no view has its own sizing code.

## Contracts
**LANG** (`grammar.js`) — required: `name, flag, bcp47, letters` (space-separated units, multi-character allowed),
`forms(entry, word) → { sg: [a, the] | null, pl: [two, the] | null } | null` (a language without `forms` gets no flag).
Optional: `dir` (`<html dir>`, swipe direction), `keepCase` (example words keep their case), `spell(letter)` (the spoken letter name), `fold(text)` (search),
`voices` (RegExp of preferred voice names), `checkForms(entry)` / `checkWord(entry)` → message.
Module data, only when a module lists it in `needs`: `numbers` (1–10), `teens` (11–20), `tens` (10, 20 … 100) — 10 words each, `sayLetter(name, word, inside)`.
Optional data the letters module uses when present: `groups` (letter groups, e.g. `'ch sch'`), `sayGroup(group, word)`, `alike` (letters that sound the same, e.g. `'â=î'`; never offered together in a game).

**STRINGS** — the engine reads `sections`, `find`, `info`, `noVoice`, `sgpl`, `none`, `noneLine`, `thats`, `cheers`, `cheer`, `wow`, `wrong`, `index { az, grp, other }`,
`search { placeholder, hint, none, results }`, `words`, `headCount`, `version`, `exclaim`, `listing`, `then`, `range`, `install`, `installBtn`, `profile { <id>, ages }`,
`also`, `aria { … }` (every `data-aria` key of abc.html, plus `leftHand`, `rightHand`). `APP.ui()` is the merged table, cached per language. Templates use `{name}`-style slots; an object template is chosen by `g`, then by plural category.

**WORDS** — `const w = WORDS(code); w(id, { w: 'va/că', … })`; `/` and spaces mark syllables; `homonym: 'orange'` allows the same spelling as that concept
(orange the colour / the fruit); `syn: [{ w: 'ghea/tă', def: 'gheata', pl: 'ghete', g: 'f', plDef: 'ghetele' }, …]` lists synonyms as full words (own syllables and forms, checked like any word): each is its own dictionary item (`<concept>~<n>`, same picture and concept), every name shows the others under "also called" (tap to hear, 🔗 to its Read page), the "What is it?" card lists all names, and search finds any name or form.
**INFO** — `const i = INFO(code); i(id, { title, lines: [[emoji, sentence], …] })`. **C** — `C(id, pic, { gloss })` (`gloss`: a note for translators, not read by the app).
**GROUP** — `GROUP(id, 'member ids')`: the group is a concept too (its word names it); a concept is in at most one group (index Groups mode, Groups module).
**ART** — `ART(id, svgBody)` (viewBox 0 0 32 32).

**MODULE** — `{ section, ages: [from, to], needs?: [LANG fields], build(code) → S, tiles: [TILE], check?(code, S, strings, report) }`.
`build` reads its text from `this.strings[code]`; other `.js` files in the module folder load before `module.js`; a failing `build` is a check error.
Module strings: `{ tiles: { <tileId>: [learn label, game label] }, games: { <key or group.key>: spoken question }, say?: { <concept>: Learn line } }` + the module's own keys
(e.g. the clock's `hourCycle` (`h12`/`h23`; absent → the locale's Intl hour cycle), `hours`/`oclock` (12 each), `time.m0…m55` with `{h}`/`{next}`/`{oclock}`,
`parts` (words for the module's shared hour → part-of-day table), `when` (`{time} {part}`), `say`, `day`). A question template receives every field of the target (or of the round's `subject`) plus `{the}` (falling back to `name`).
Every language must have every key the base language's module strings have (checked); a language with no strings for a module hides it.

**TILE** — `{ id, icon (emoji or short text), view, items: S → ITEM[], game?: { type, items? (default: items; `noPlay` items dropped), prompts?, lower?, ask? },
index?, search?, section?, ages?, perLanguage? }`.
`prompts` (default `['glyph']`; repeats weight the draw): `glyph` shows `prompt`, `word` shows `promptWord`, `voice` shows the listen icon.
`lower`: small letters in half the rounds. `ask`: a key, or `(item, round) → key` with `round = { lower, prompt, subject, look, missed }`; default the tile id.
`index`: the ⊞ button. `search`: its items in the universal search. `perLanguage`: its items differ by language (letters, the dictionary);
every other tile has every item in every language (checked).

**ITEM** — `id` (stable), `label` (short text, sort key), `name` (spoken), `say` (Learn line), `big`/`bigClass`, `color`, `nav`,
`key` (the keyboard key that picks it, and from a hub opens its tile), `word`, `pic`, `pics` (objects in the card, Count row and how-many question),
`pl` (plural word, Count), `examples [[word, pic, inside]]`, `concept`, `concepts` (other concepts it shows — linked too), `related` (see-also concepts, linked by picture and word, e.g. a clock → hourglass, sundial; each opens that word's page, and that page links back to the item's tile; checked to be concepts), `alts` (the concept's other names: `[{ id, w }]`, built),
`parts [{ say, color? }]` (the card's parts explorer, below), `unit`, `w`/`syl`/`forms` (Read), `n` (Count),
`backdrop` (a CSS background the card and dial views paint behind the whole screen via `APP.backdrop`, e.g. the sky at that hour; it must keep `--text` ≥ 4.5:1
and `--muted` ≥ 3:1 — the hub and every other view clear it), `at` (the item's place on a scale, e.g. minutes of the day; links pick the nearest) + `dial` (dial view: the item's value and the shared dial `{ face, cap, cycle, step, aria { less, more },
hands [{ turn, snap, len, body }], read(value) → { text, name, say, backdrop } }` — the module draws, the view only turns),
games: `bubble`, `lower`, `bubbleColor`, `prompt`, `promptWord`, `the`, `noPlay`, `smallBubble`, `pictureBubble`, `learn` (id of its learn item when it differs),
`sound`, `bubbleArt` (HTML picture), `among` (choices only from items with the same `among`), `members` (sort game; built by CONTENT too),
`plural`, `a` + `g`, `thats` ({ name, g } for "That's …", built). Two choices in one round never share a `sound` or a look.

**VIEW** — required `el, show(sayIt)`; optional `line()` (what the language announcement and Space say), `select(item)` (a key picked this item; `choices()` limits which),
`step(d), leave(), resize(), reset(), beforeLang() → state, afterLang(state)`, `state()` (tests), flags `arrows` (the shell draws ‹ › with `navFace(item)`, default `item.nav`),
`play()` (the shell shows ▶ and toggles it; with `playable(item)` only for the items it accepts — Space follows the same rule), `swipe, fullHeight, keepScroll, indexFace(item) → HTML, indexSort`.
A single line is `speak(text, PAUSE.x)`. Anything multi-step goes through `APP.sequence(scope, steps, { button, finale, at })` with
`steps = [{ light?, say?, pop?, delay?, pause? (default 200 ms) }]`: it speaks, lights (`.on`), reveals and celebrates step by step; a new sequence cancels the
previous one; the shell calls `APP.stop()` on leave, language switch and background, and views call it when they step. One-off feedback is
`APP.celebrate(el, big)`; taps go through `onTap`/`onTapIn`.
State: `APP.idx` (current item), `APP.streak`, `APP.stars`. Other `APP` helpers: `L, ui, t, mt, icon, exclaim, alphabet, hands, items, item, gameItems, tile, screen, indexOf, step, neighbors, shown, saveIdx, light, reveal, playing, stop, celebrate, sequence, synonyms, addStar, fit, fitText, backdrop`;
any `[data-t][data-id][data-play]` button opens that tile at that item (`openTile(id, play, quiet, itemId)`, one render); `APP.stop()` clears `.on` in the stage, the info list and every `fullHeight` view;
`APP.links(item, el, brief)` fills `el` with the item's link chips (info, same concept in other tiles — the one with the nearest `at` when items carry one —, `related` as picture + word chips, learn ↔ play) and hides it when empty — every view uses it; `brief` (dial) and play view keep only info and learn ↔ play. On a backdrop the chips get the `--card` background (contrast).
Space/Enter on a focused button presses that button; elsewhere they play (▶) or say the view's `line()`.
**dial** — a face with hands the child turns: a drag that starts anywhere on the face moves the hand nearest the finger (within `GRIP.near`°, else the held hand) by the finger's angle change (no jump to the finger);
hands are geared through one value (minutes: the minute hand drives the hour hand, crossing 12 changes the hour, the day wraps at `cycle`); a drag snaps on
release to the held hand's `snap` (hour hand: whole hours, minutes kept; minute hand: `step`) with a tick at each snap point; a movement under `GRIP.tap` px is a
tap — on the other hand it picks that hand, elsewhere it turns the picked hand to the tapped number (hour hand: to that hour, minutes kept); − / + step by `step`; a second touch during a drag is ignored.
Keyboard: the face is a focusable `role=slider`; ↑/↓ (PgUp/PgDn) step the held hand by its `snap`, Space/Enter switch the held hand. The digital time,
spoken name and backdrop follow the value; the time is spoken on release only. ‹ › sweep the hands to the next item's `at`.

**Parts explorer** (card view, any item with `parts`: rainbow bands, animal families, opposite pairs) — one engine feature driven by data.
A part is `{ say }` plus optional `color`. Every part is shown once: `CONTENT.group` draws each member as a button (picture, caption under it) (`captions`,
default the member's word) and each part is at least `--part-min`; tapping a part says it, tapping the picture anywhere else steps to the next part
(no dead taps). Parts with a `color` (the rainbow's bands) also get a strip of contiguous swatches under the picture (`#parts .pt`, ≥ `--tap`, the column's width — clear of the edge-swipe gesture): tap or drag a finger across it (`onScrub`), each part lights (`.on`, the others dim) and is spoken, held for `PAUSE.hold`; until it is used an idle
hint (👆 `icons.drag`, after 3 s, 3 times, static under reduced motion) shows it can be touched. ▶ (items with parts) says the name and every part in order.
A learn card too tall for the screen first takes the `#learn.tight` tokens, then scales (`APP.fit`).

**GAME** — hosted by the `play` view, which draws the question line the same way for every game (🔊 + text, tap repeats the spoken question):
`{ needs (min. items, default 2), pool(items, streak) → candidates, vary?(target) → round.look ({ vars } joins the question's fields; the rest is for show), caption? (bubbles show the item's name under the picture), show(target, round, spokenQuestion, subject) → { text (never reveals the answer), picture: HTML } }`.
Every picture or colour bubble shows its name under it (`.bname`) unless the question shows the name as text (`find` with a `glyph`/`word` prompt) or the tile sets `game.caption: false` (clocks: the name would give away the time).
Numbers 1–10 carry `tally: n` instead of fixed pictures: card, count view and game draw n of a random countable word (`CONTENT.countable(code)`, `APP.countable()`, `APP.tally(item)`) each time.
`howmany` counts a random countable word (a plural, no mass/unique words), or — with the tile's `game.fingers` concept, a quarter of the rounds — raised fingers (`APP.hands(n)`, shared with the count view).
The play view offers 2 choices, 3 from a streak of 3, 4 from a streak of 8, and draws missed targets more often but at most 3× (`RULES` in play.js, weights stored as `w`);
a target does not come back before half the pool was asked, a `subject` not before 8 others.
An item with `members` asks about one member per round (`subject`, kept across a language switch); the question's `{name}`/`{the}` come from it.

**config** — `name` (title, install text; checked against the head and the web manifest), `version` (x.y.z, shown with the build hash at the foot of every hub),
`icons { key: text }` (every UI icon; `data-icon` in abc.html), `languages` (flag order), `modules`, `sections [{ id, icon, play? }]` (tab order, exactly one `play`),
`profiles { id: { ages, art? } }` (ascending), `defaultProfile`, `baseLanguage`.

## Recipes
**Add a word** — `abc/concepts.js`: `C('wolf', '🐺');` then in each `abc/lang/<code>/words.js` (`/` marks syllables):
```js
w('wolf', { w: 'lup', def: 'lupul', pl: 'lupi', g: 'm', plDef: 'lupii' });
```
**Add a "What is it?" card** — `abc/lang/<code>/info.js`: `i('wolf', { title: 'Lupul', lines: [['🐺', '…'], ['🌲', '…']] });`

**Add a language** — create `abc/lang/<code>/{grammar,strings,words,info}.js` (copy `en`), add the code to
`config.languages`, add `abc/modules/<id>/lang/<code>.js` for each module, run `node tools/check.js --fix`.
The flag, tabs and offline cache follow automatically; a module with no `lang/<code>.js` stays hidden, partial strings are errors.
Extend `tools/smoke.js` (the flag list and the `ASK` question patterns).

**Add a module** — `abc/modules/<id>/module.js`:
```js
MODULE('fruit', { section: 'disc', ages: [2, 6],
  build(code) { return { fruit: CONTENT.set(code, [{ id: 'apple', ex: 'tree' }, { id: 'banana' }], this.strings[code]) }; },
  tiles: [{ id: 'fruit', icon: '🍎', view: 'card', items: S => S.fruit, index: true, search: true, game: { type: 'find', ask: 'where' } }] });
```
plus `lang/<code>.js` with `MSTRINGS('fruit', code, { tiles: { fruit: ['Fructe', 'Găsește fructul'] }, games: { where: 'Unde e {the}?' } })`,
add `'fruit'` to `config.modules`, run `node tools/check.js --fix`, and add the question pattern to `ASK` in `tools/smoke.js`.
The Play tile is created from `game` (1 learn ↔ 1 game).

**Add an age profile** — `config.profiles.<id> = { ages: [from, to] }` (ascending order), `ART('<id>', svg)` in `abc/art.js`,
`profile.<id>` in each `strings.js`; update the profile checks in `tools/smoke.js`.

**Add a view or a game type** — `abc/core/views/<id>.js` with `VIEW(id, {el, show, …})` (contract above; the id must equal the file name;
its element is created in the stage — or in the body for `fullHeight` — if `abc.html` has none; add markup and CSS there only for fixed controls) or
`abc/core/games/<id>.js` with `GAME(id, {needs, pool, show})`; run `node tools/check.js --fix`.

## Checks
```
node tools/check.js --fix        # after every change: all static checks, rewrites abc/manifest.js
node tools/fast.js [sizes] [dir] # ~13 s, no server: every language × hubs, learn tiles, games × 7 sizes — after any CSS/markup/view edit
node tools/smoke.js [url] [WxH]  # ~40 s per size, repo's parent folder served on :8765 — CI runs it; locally when a change touches what it covers
```
CI (`.github/workflows/check.yml`, jobs `check` and `browser`) runs check, fast and smoke (360×640 and 320×568) on every PR and push to main
that changes more than `*.md` / `docs/**`.
