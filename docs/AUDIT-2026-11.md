# Architecture audit — November 2026

Six independent expert reviews (agents) of `abc.html` + `abc/` at commit `8844ba6` (v0.9.0-preview).
Line numbers refer to that commit. Severity: **H** high · **M** medium · **L** low.

Round 1 — languages & data: i18n architect, adversarial skeptic, localization-pipeline expert.
Round 2 — growth: module/content-type architect, planet-scale i18n expert, product strategist.

## B. Data & language model (round 1)

All three reviewers agreed:

1. **Stable ASCII concept ids** (`cow`, `bull`, `kite`, `bat.animal`), not emoji. Emoji collide (☀️ vs ☀ differ by U+FE0F; 🐂 ox/bull), some concepts have none (planets), new emoji render as boxes on old Android. The picture becomes a field.
2. **One folder per language**; each language owns its vocabulary (it chooses which concepts it has). Concepts are language-neutral (`pic`, categories, colour hex, **gloss / translator note**).
3. **Store every form a strict reviewer checks** (e.g. RO `def: 'vaca'`, `plDef: 'vacile'`); the generating rules become a *check* that warns on mismatches.
4. **Bare plural, not "two …"** (`pl: 'vaci'`), so "trei vaci", "douăzeci de vaci" become possible.
5. **Letter examples chosen explicitly per language** (not by row order of a shared file).
6. Use **Intl**: `PluralRules` (RO "de" for 20+ is exactly category *other*), `ListFormat` ("… și violet"), `Collator` (index order with ă/ș/ä), `Segmenter` (graphemes instead of emoji regex).
7. **Review status per entry** (`draft` / `reviewed` + hash) and a review sheet showing entries exactly as the app renders them.
8. **Closed sets must be complete** (rainbow, seasons): a set appears in a language only if every member exists.

Disagreement: JSON + lazy fetch (architect) vs plain JS `W('cow', {...})` calls loaded with `<script>` (localization expert). **Chosen: plain JS** — no async loading, comments allowed for translator notes, lazy loading can be added later without changing the format.

## C. Modules & new content types (round 2)

Adding physics simulations, a periodic table (grid), the body / immune system (diagram with tappable regions, step-by-step story) breaks today's design:

- **H** Screens hard-coded: a new view needs edits in `abc.html`, CSS and six places in `app.js` (render, announceLang, keydown, swipe, resize, openIndex).
- **H** One game engine around a single target; sort, order, pairs, drag-match, find-on-diagram don't fit.
- **H** Everything loads at startup; content rebuilt on every language switch.
- **H** Each language file must know every topic; no per-module strings, no fallback.
- **M** Items mix data with HTML (`big`, `nav` strings); state is global for one topic; no age/level concept; keyboard assumes `it.key` + card view.

Target: **modules** (`abc/modules/<id>/{module.js, data.js, *.svg, lang/<code>.js}`) on a **shell** with shared **views** (card, grid, diagram, sequence, sim, custom) and **game types** (find, find-grid, find-region, sort, order, pairs, true-false, drag-match). Lifecycle `mount / unmount / onLang / announce`; services `ctx = { t, speak, sfx, stars, info, store (namespaced), lang, age }`. SVGs contain shapes only (`data-k="body.lung"`), labels are translated strings placed over them. Learn ↔ Play pairing stays automatic (each view declares its game; a game with unmet `needs` is hidden, never a crash).

## D. Any language on Earth (round 2)

Breaking assumptions (ranked): letter = one code point with case; reading split by code points; syllables marked with "/"; example search with startsWith/includes; grammar hard-coded as articles + "two X" + a fixed 4-cell table; sentences built by string concatenation; ASCII digits and number words only 1–10; no `dir` (RTL); locale codes cut to 2 letters, flags = countries; Latin-only fonts; keyboard/IME and Latin-only diacritic stripping.

Proposals:
- **Writing-system model**: `units` (letters / kana / jamo / hanzi / multi-char letters) with glyph, contextual forms, optional case pair, name, sound, optional audio clip; `segment`, `dir`, reading aids (pinyin, zhuyin, furigana).
- **Compute with Intl**: plural category, digits (`numberingSystem`), collation, lists, graphemes. **Store as data**: units, sounds, syllables/morae, readings, gender/classifiers, `dir`, number words (1–20 + composition rules or audio).
- **Templates** in an MF2-like syntax with a ~3 KB interpreter (no build step).
- **Voice chain**: recorded clip → local (`localService`) voice → visible "🔇 no voice". Never another language's voice. Per-script timeout factor.
- **Fonts**: per-language subsets generated by a tool from the glyphs actually used (CJK ~15 KB instead of ~16 MB), cached only when the language is chosen.
- **Language readiness levels**: L0 UI · L1 vocabulary with voice · L2 letters/reading · L3 science (glossary from an authoritative source + expert review). Hubs hide topics above a language's level.

## E. Product scope (round 2)

- One experience for ages 2–12 is not viable (Khan Academy Kids ends ~8; Duolingo ABC is a separate app; PBS Kids ~2–8). **One engine, age profiles**: Little 2–4 (≤4 tabs, ≤6 tiles per hub, voice-only, no "coming soon"), Explorer 4–7 (themed worlds), Scientist 7–12 (search, progress, text).
- **Languages**: review load explodes (100 modules × 50 languages = 5,000 sign-offs). Ship RO/EN/DE complete; add a language only with a native reviewer, a voice tested on the family's devices, and a clean `check.js`. Never ship unreviewed machine translation to children.
